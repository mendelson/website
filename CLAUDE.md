## This repo

`mmendelson.com` — the personal hub, and **the apex of the domain the whole
family hangs off**. Static site generated by `build.py` (Python stdlib only, no
packages, no lockfile); content fragments in `content/`, one shell in
`templates/base.html`, output in `public/`.

- **`build.py` is the source of truth for URLs.** `PAGES` renders, `REDIRECTS`
  bounces, `PRESERVE_QUERY_REDIRECTS` carries `?trackId=…` through the hop to
  `apps.mmendelson.com/tracker/`. The README's tables are a human-readable
  summary of those dicts and drift if edited alone.
- **`CUSTOM_DOMAIN` at the top of `build.py` decides the whole build.** Empty →
  `mendelson.github.io/website` with `BASE = "/website"` on every link and no
  `CNAME`; set → apex, `BASE = ""`, `CNAME` emitted. It is currently
  `"mmendelson.com"`.

### Hosting — verified 2026-09-13, not assumed

The apex is served by **GitHub Pages** (`185.199.108–111.153`,
`server: GitHub.com`), DNS at **GoDaddy** (`ns41/ns42.domaincontrol.com`). The
zone also carries **GoDaddy email** — MX `smtp.secureserver.net` and an SPF TXT
— so any nameserver move has to carry those or the mail stops.

**The sibling hosts are each somewhere different, and guessing costs a session:**
`apps.mmendelson.com` is GitHub Pages (`apps-website`), `run.mmendelson.com` is
**Cloudflare Pages** (`corridas.pages.dev`), and `api.mmendelson.com` is the
`strava-backend` FastAPI on **Render**. So "the sites are on GitHub Pages" is
false for two of the four.

**The repo named `mendelson/mywebsite` is NOT this site.** It is an AngularJS
skeleton last touched in 2018, with no CNAME. The live one is
`mendelson/website`, confirmed by building locally and diffing against the
served homepage byte for byte. Check the same way before believing either.

### Redirects: the 200-with-JavaScript shape is forced, not chosen

`redirect_html()` (`build.py:164`) emits a meta-refresh page with a
`location.replace()` script. It answers **200**, not 302. That is not a
preference — GitHub Pages serves files and runs no per-request code, so it
cannot emit a 302, cannot set a response header, and exposes no access log.
Anything needing a real status code, a header, or a log **cannot live on the
GitHub Pages deploy**, however small it looks.

### Printed-card redirects (`cards/`, `functions/`, `batches.py`)

Trackable short URLs for printed card batches — `mmendelson.com/<id>` → 302 to
the app site, one row per scan. Runs as a **Cloudflare Pages Function**, for the
reason above. Full operator doc: [`cards/README.md`](cards/README.md).

- `cards/batches.json` is the only file to edit to add a batch. `batches.py`
  validates it and generates `functions/batches.generated.js`, which is
  **committed** so the edge bundle never depends on build ordering;
  `tools/check_cards.py` fails if the two drift.
- **The module is `batches.py` and the directory is `cards/` on purpose.** A
  `cards.py` next to a `cards/` directory resolves by import precedence most
  readers do not know, so the names were split.
- **Only `id → destination` reaches the edge.** Headline, quantity, print date
  and distribution point stay in the JSON for querying; a gate asserts each
  value stays out of the generated bundle.
- **An id that collides with an existing path is a build failure.** The reserved
  set is derived from `PAGES` and `REDIRECTS`, so a new page defends its own
  path automatically. This matters because `/r/`, `/g/`, `/t/`, `/cv/` and eight
  more single-letter aliases already exist — a card printed with one of those
  would have been dead on arrival.
- Gates, both of which print a check count and fail on zero (rule 7):
  `python3 tools/check_cards.py` and `node tools/test_middleware.mjs`. The
  second imports the real middleware and runs it against a stubbed Pages
  context, so 302-not-301 and "the log never blocks the hop" are measured, not
  asserted in prose.
